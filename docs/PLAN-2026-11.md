## 2. 架构评审

### 2.1 合理的部分

1. **两层隔离**（0.9.1 起）：`lib/computer-use/` fork（修改点注释索引）+ 自研模块独立可单测；不再有补丁脚本层。
2. **（历史）幂等补丁器**：0.4–0.9 期间用 JSON 锚点补丁维护 vendored 改动；0.9.1 起改为 fork，补丁器已删除（git 历史可查）。
3. **依赖注入**：`operator-tools` 不静态 import `@deepseek-ai/dsh-tools` / `dsh-attachment`，由 vendored `apply` 传入，仓库内可无宿主环境单测。
4. **单一入口**：`index.js` 做执行位自愈 + re-export，没有第二套生命周期。
5. **失败可降级**：截图缩放失败回退原图、AX 失败回退视觉、图片存储失败回退纯文本，观察链路不会因单点失败整体报错。

### 2.2 结构债（按严重度）

| # | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |
| A1 | ~~补丁注入面过宽~~ **已解决（0.9.1）**：直接 fork `lib/computer-use/`，删除补丁器与 62 个锚点补丁 | — | 已完成；差异与同步流程见 `docs/FORK.md` |
| A2 | **AX 助手只编了 arm64**（`file` 显示 Mach-O arm64），每次调用 spawn 一个进程（140–670ms） | Intel Mac 直接没有 AX（静默降级）；高频调用有固定开销 | P1：lipo 出 arm64+x86_64 通用二进制 + `build:ax` 校验架构；P1：可选常驻 daemon（socket），保留 spawn 兜底 |
| A3 | **配置/注册分散**：Config schema 在 vendored，resolve 在 vendored，工具注册在 `operator-tools`，冲突检测在 apply | 新增配置要改两处，契约容易漂 | **推迟到专门批次**：`Config`/`resolveComputerUseConfig` 已在 fork 文件内被多处直接消费，抽公共模块需同步改多处并承担上游 diff 成本，收益低于回归风险；当前以「新配置两处同改」约定代替，待 fork 面再扩大时统一 |
| A4 | **工具输出契约不一致**：只有 `list_windows` / `verify_state` / `ax_press` / `zoom_region` 带 `schemaVersion`，13 个 GUI 工具的输出没有 | 跨版本解析不稳 | **已完成（0.21.11）**：在 `registerComputerUseTool` 统一包装——schema 补 `schemaVersion: {type:"integer"}`、execute 结果补 `{schemaVersion:1,...}`（DSH 校验器不允许 output 属性带 `required:true`，故字段可选但实现保证返回）；`check-p0` 增静态守卫；顺带修 CI 的补丁器步骤（fork 化后改 `check-p0`） |
| A5 | ~~测试目录混用~~ **已解决（0.9.0）**：`test/*.test.mjs` 用 node:test（70 项），旧四套保留作手工冒烟；fixtures 以内联构造（合成 JPEG / 假 internals）代替独立目录 | — | 已完成；基准数据用 JSON（仓内零依赖解析） |
| A6 | **单例状态**：`frontmostCache` / `windowCache` / ax settings / audit path 都是模块级单例 | 同一 host 多会话并发时共享，行为可解释但无隔离 | 可接受（配置本就是 profile 级）；文档写明即可 |
| A7 | **安全层缺失**：危险动作靠 POLICY 提示词约束，无代码级 guard | 模型误点删除/支付/发送无法拦截 | P0：自研 guard 模块（见 3.2），参考社区思路但我们自己实现 deny/confirm 语义 |

### 2.3 与竞品的架构对比

- 官方：seam（35 行单槽位）+ provider（123 行）**只做注册**，观察/动作全在 Cua Driver 原生层（53 MB，host 进程内，崩了带走宿主）。强在契约，弱在工程惯性（无重采/降级/并发）。
- 社区 0.3.1：薄壳 + 外部引擎（每次 `spawn cua-driver`），无二进制则 11/12 工具失效；错误吞成 `{ok:false}`。
- anionex 0.3.7：host 单行挂载 + 901 KB native + 私有 SkyLight 符号 + 租约系统；强但依赖重、暴露渐进（与全局挂载定位冲突）。
- dsh-orb（上游）：悬浮球宿主 + preset 形态，功能范围大、维护单人。
- **我们**：纯 JS 全局挂载 + 自编译 128 KB helper，无外部引擎、无 native 崩溃风险；架构简单但注入面较宽。

## 4. 借鉴 vs 自研

> 借鉴不丢人（MIT + 注明来源 + 改进），关键是「借鉴的东西有没有被我们改成优势」。

### 4.1 明确借鉴

| 来源 | 借鉴内容 |
| --- | --- |
| dsh-orb（上游，MIT） | 13 个 GUI 工具骨架、截图/输入实现、坐标与策略文本 |
| 社区 `dsh-computer-use@0.3.1` | AX 文本树观察思路、入口统一 guard 的思路 |
| anionex `0.3.7` | AX 行格式（role/title/value/位置）、结构化 effect「只报事实」的思想 |
| 官方 `@deepseek-ai/dsh-computer-use` | `ActionResult.effect` 语义、`clipped/sourceBounds` 元数据、`verify_state` 概念、schemaVersion 契约思想 |

### 4.2 自研（竞品里没有对应实现，或实现方式不同）

| 自研点 | 说明 | 证据 |
| --- | --- | --- |
| **截图降 token 管线** | `screencapture → sips -Z 1280 + q80`，手写 JPEG SOF 解析、失败回退原图；竞品都是原图/整窗 | A2 基准 5 任务 +¥0.22 vs 官方 +¥0.70 |
| **`actionEffect` 截图 sha1 判定** | `confirmed / suspected_noop / unverifiable`，用前后截图 sha1 而非 AX 树 hash；配合「noop 不附图」 | 真机连点触发 |
| **多窗口坐标归一化** | 截图是「同 App 窗口 union」时，AX 坐标必须按 captureRegion 归一化（0.5.3 修复），竞品无此问题意识 | 两 Finder 窗口连点验证 |
| **前台 JXA 缓存** | listScreens + inspectForeground 共用 250ms 缓存 | 857ms → 217ms |
| **浅 AX 树阈值** | 按「格式化后保留节点数」而非原始节点数判断 Electron/Web | Harness 13 节点被过滤、系统设置 33 节点保留 |
| **查询/验证工具面** | `list_windows` / `screenshot_window` / `verify_state` / `ax_press` / `zoom_region` | 竞品无同款 |
| **无内容审计日志** | 只记事件/数量/布尔/耗时，脱敏 + 5MB 轮转 | `~/.dsh/dsh-operator/audit.jsonl` |
| **幂等补丁器 + 基准协议** | JSON 补丁 + `--check`；A/A2/B 组同口径任务 | 54 补丁、三组数据 |
| **策略瘦身** | 8.4KB → 3.9KB 且保住上游坐标段原文（backgroundPolicy 依赖） | check-p0 断言 |

### 4.3 自研是否是真优势

是，但要限定：

- **真优势**：token 成本（3.6×）、动作后重采+结构化校验、纯 JS 无外部引擎、查询/验证工具面、可运维（审计/基准/补丁可回放）。
- **不是优势（别吹）**：动作语义契约不如官方 `ActionResult` 完整；AX 元素 token/snapshot 语义是简化版；语义护栏刚补（0.9-3）；Windows/多屏没验证。
- **结论**：定位「视觉优先、可审计、低成本、零外部依赖的全局 GUI 手」，而不是「官方 Cua Driver 的替代品」。官方给的是引擎，我们给的是「顺手的手」。

## 8. 可持续性设计（让插件活得久）

1. **依赖面最小**：运行时无第三方 npm 依赖（zod 用 profile 已有）；无外部引擎、无 native 进程内嵌；唯一原生件是我们自编译的 128 KB Swift helper，可 `build:ax` 从源码重建。
2. **上游同步可对照**：0.9.1 起 fork（`docs/FORK.md`）；`scripts/fetch-upstream.sh` 拉上游 tarball 人工 diff，合并后跑全部测试。补丁机制已删除，git 历史仍可查旧补丁集。
3. **DSH 契约测试**：把「defineTool/schema 规则、apply/inject、附件接口、systemPrompt section」写成 contract tests；DSH 升级先跑一遍。0.4.0（schema `required:false`）和 0.6.0（嵌套 `additionalProperties`）两次加载失败，都是靠「真实 defineTool 注册」冒烟测试抓到的——这条已固化成断言。
4. **版本与兼容政策**：SemVer；README 放兼容矩阵（DSH 版本 × macOS 版本 × helper 架构）；所有新工具输出带 `schemaVersion`；弃用先文档标记一个版本再移除；CHANGELOG 每版必写。
5. **无遥测 + 可诊断**：不做数据上报；新增 `scripts/doctor.mjs`（可跑成 CLI）：检查 DSH 版本、profile 挂载、helper 架构与执行位、屏幕录制/辅助功能权限、`screencapture` 可用、audit 目录可写，输出一段脱敏诊断块贴 issue。
6. **发布工程**：GitHub Actions（macOS runner：npm test + 补丁 --check + schema 校验 + 构建 helper + 打包检查）；tag → release notes；`docs/RELEASE-CHECKLIST.md` 真机清单（install → 重启 → 五条 live-smoke → 回滚）。
7. **文档即产品**：README 三十秒上手（一条命令 + 一张动图）；审计/基准/路线图全部公开；「未验证」用统一标记（如 `⚠️ 未验证：Windows`）。
8. **反馈闭环**：issue 模板（环境/复现/诊断块）；缺陷修复写回归用例；失败样本不落敏感内容。单点维护的风险靠「可回放补丁 + 自动化测试 + 文档」降低，而不是靠某个人。

## 10. 0.9.0 实现要点（二稿）

- **首帧懒观察（安全版）**：`firstFrame` 默认 `auto`——pre-step 观察只在三种情况发生：① 本会话 10 分钟内有过 GUI 动作（`recapture` 记录时间戳）；② 桌面选区特例；③ 配置显式 `eager`。纯聊天会话 0 张图；GUI 会话行为不变。没有图时模型可先调 `wait`（它内部 `recapture` 会返回观察），POLICY 里写明这一条，避免盲点。
- **noop 不附图**：`recapture` 在 `suspected_noop` 时把 screens 置空、只回文字 note（上一步截图还在上下文）。
- **guard**：`lib/guard.js` 纯函数判定（动作类型 + 目标文本/角色 + 路径），命中危险词（删除/卸载/清空/格式化/支付/购买/发送/退出登录）、密码类角色（AXSecureTextField 等）、越权路径 → 拒绝并返回需 `confirm: true` 的事实；`COORDINATE_FIELDS` 已展开进全部动作 schema，加一个 `confirm` 字段即可统一放行。
- **测试基建**（✅ 完成）：`node --test` + Node 内建覆盖率（自研 lib 91.65%）；fixtures 以内联构造替代独立目录；错误注入（sips/`screencapture` 失败、取消、坏参数、helper 失败）；`scripts/bench.mjs`（JSON 任务/结果 + check/report/record）。

> daemon 常驻（实测 helper spawn 60–80ms）：收益小于一次网络/模型往返，继续暂缓；0.10.5 已把 AX 与截图并行，等价省掉一次串行 spawn。
